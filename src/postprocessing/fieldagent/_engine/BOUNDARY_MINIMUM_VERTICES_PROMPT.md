# Additional goal: minimum necessary vertices across ALL selected parcels

The user's primary goal for this run is substantially fewer boundary vertices for EVERY selected parcel, not just an attractive single example. The host sends one target at a time and visits the full supplied target list. A target that still contains hundreds of staircase vertices is normally unfinished: attempt a concrete simplification unless image evidence, topology, a failed gate or exhausted budget gives a specific reason not to.

Within the UNCHANGED quality gates, seek the smallest defensible vertex count rather than a conservative first improvement. Long straight or nearly straight stretches should use their necessary endpoints; keep extra vertices only where real direction changes or curvature require them. A visually simple monotonic side or shallow arc normally needs about 3--4 structural vertices for that side, not 10--30 staircase samples. A simple whole ring may therefore be reduced to roughly 4--8 vertices; do not preserve a dozen points merely because a rasterized preview looks jagged. There is no universal ten-point target and no reason to sample every Nth pixel by default. Use image continuity and full coordinates to identify actual corners and curves. Treat preserving pixel stair steps as a cost, not a safety benefit.

For a target like a parcel with two long sides and one broad lower turn, first identify the endpoints of the long sides and the one or two real turning points. Try the smallest explicit retain-vertex proposal that represents those structural points. If the strict gate rejects that proposal, inspect the rejection and add only the minimum points needed to pass; do not jump directly back to the 14--30 point candidate. Record the rejected low-point attempt and the reason for each added point. The requested point count is a soft geometric objective, while validity, overlap, image drift and area checks remain hard gates.

shared_boundary_protection identifies exact current shared edge segments and their original endpoint indices. A whole-ring simplifier may fail because it alters only a small shared stretch, while the other long edges are freely simplifiable. In that case use your own retain_vertices list that includes the protected endpoints and preserves each protected connecting segment, while removing redundant vertices elsewhere; or replace a free local arc. Do not conclude that all vertices are necessary merely because a global tool failed. These indices are geometric diagnostics, not an optimization result or permission to skip the gate.

Compare offered passing simplification candidates by vertex count AND actual image alignment. A correction candidate is worthwhile only with visible displacement evidence and the correct task type; never relabel simplification to escape its gate. Existing candidates and tools are allowed. If your visual judgment identifies redundant bends they missed, author explicit retain-vertex indices or replace a local arc. Record the true method and the specific arc/points.

After inspecting a passing preview, explicitly evaluate whether fewer points remain feasible within the same gate. If budget permits a better proposal, compare it before committing; or commit with done=false and use the updated indices to continue. If this is already the lowest justified passing option, commit with done=true and explain the remaining necessary bends. Do not end simply because the first preview passed. remaining_target_calls_including_current includes this response; leave at least one subsequent response to inspect and commit a new proposal. With only one response left, commit an already observed accepted proposal or retain/review; an unobserved new proposal cannot become final.

Finish each target with an honest verdict: successfully simplified, no supported further reduction, validation blocked, or budget incomplete. The host records actual point counts. Never claim unvisited parcels were processed, or claim an uncommitted preview as a repair. Finite coordinates, identity, components/holes, cumulative shape limits, overlap and shared-boundary checks remain mandatory and identical to the other modes.
